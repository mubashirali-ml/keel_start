## Summary

Creates the whole `frontend/` project (React 18 + TypeScript + Vite 5 + Tailwind 3, exactly the
ADR-0025 npm set) so the nine wave-4 screen tickets can build in parallel against a finished shell:

- **Brand (`src/brand`)**: the sailboat mark (triangular sail, shallow hull, short keel fin; flat
  `currentColor` SVG on a 32 px grid) beside the "Keelstart" word mark, `BrandName`/`useBrandName`
  (from `PublicConfig.brand_name`, compiled fallback in `brand.ts`), tagline constant, disclaimer
  line, `pageTitle()` / `landingTitle()` / `usePageTitle()`, footer line with `[COMPANY LEGAL NAME]`.
  `index.html` gets its title and Open Graph tags from the same constants (a small Vite plugin).
  Favicon SVG plus 32 px / 180 px PNGs and a 1200x630 OG image (mark, word mark, tagline) rendered
  from the same mark by `launch_agents/devtools/brand_assets.py`.
- **Design system (`src/design`)**: `tokens.css` (every color for light and dark; primary a deep navy
  `rgb(27 54 130)`, light blue in dark mode), Tailwind bound to the tokens only (`theme.colors` is
  replaced, so palette classes don't exist), the ADR-0019 type scale, radius, shadow, motion and
  `prefers-reduced-motion`. Every ADR-0019 component plus `TrustNote`, `PlanGate`, `Banner`,
  `FormField` + `useZodForm`, `Switch`, `RadioGroup`, `Popover`, and helpers (`Menu`,
  `SegmentedControl`, `LoadingBlock`, `Label`). The `/design` gallery shows all 35 sections.
- **App (`src/app`)**: router with every ADR-0035 route, `MarketingLayout`, `AuthLayout`, `AppShell`
  (logo, company switcher, progress, demo-only founder switcher with "Demo mode" badge, help menu
  with Contact support, theme toggle, account menu with plan badge and Log out), the three banners,
  `RequireAuth` / `RequireAdmin` / `RedirectIfAuthed`, 401 redirect hook, `ActingFounderContext`,
  chat-plus-workspace layout (8 tabs, 6-step strip, phone Chat/Workspace switch, `useWorkspace()`
  with `openView` for `open_view` hints), 404 and "not available" pages, placeholder helpers
  (`PageFrame`, `QueryStates`, `WorkspaceViewPlaceholder`, `CompanyNotFound`).
- **API (`src/api`)**: `types.ts` mirrors the backend views field for field; `client.ts` has one
  function per ADR-0032/0038 endpoint (`credentials: "include"`, `X-CSRF-Token` from `la_csrf` or
  `MeView.csrf_token`, `X-Act-As-Founder` in demo mode, 20 s / 100 s timeouts, GET retried twice
  on network errors, mutations never); `errors.ts` (`ApiError{code, message, status, requestId,
  details}`, friendly fallbacks, last-error tracking); `hooks.ts` (every hook ADR-0035 lists,
  including `useMe`, `useConfig` with compiled defaults, `useJob` polling every 1.5 s,
  `useSubscription` → `BillingOverview`, `useChangePlan`); `support.ts` (the mailto).
- **Placeholders** for every feature folder of ADR-0035 (named page exports and default workspace
  views), each with loading, empty and error states. The login placeholder is a working form.
- **`launch_agents/devtools/ui_run.py`** per ADR-0036: `running_app` (temp dir, SQLite migrated to
  head, composed env, seeding before start, uvicorn on a free port, readiness wait with the
  `/api/health` fallback), `login` (real form), `build_frontend` (stamped, staleness-checked build
  with the gallery), `capture_matrix`, `assert_no_horizontal_scroll`, `assert_no_raw_json`, plus
  pure helpers (`compose_env`, `find_free_port`, `screenshot_name`, `wait_for_ready`,
  `find_raw_json`, `frontend_is_stale`).

### Decisions inside the ticket (worth a look)

1. **`/design` in "development builds only"**: the gallery route exists when `import.meta.env.DEV`
   or when the build sets `VITE_DESIGN_GALLERY=1`. `npm run build` (production, and what
   `verify.sh` runs) leaves the route and its chunk out entirely; `build_frontend()` (recorded
   runs) builds with the flag and stamps `dist/.ui-run-build`, so the feature run can open `/design`.
2. **`@/app` alias**: on case-insensitive file systems `@/app` resolved to `src/App.tsx` (ADR-0035
   keeps both `App.tsx` and `app/`). `tsconfig.app.json` and `vite.config.ts` map `@/app` to
   `src/app/index.ts` explicitly; everything else is `@/*` → `src/*`.
3. **Session probe while wave 3 is missing**: `useMe` treats 401 **and** 404 from
   `GET /api/auth/me` as "logged out", so `/app/*` already redirects to the login page today.
   `useConfig` falls back to compiled defaults (ADR-0038 amounts, ADR-0042 support labels) on any error.
4. **Auth-page redirect**: `/login`, `/signup`, `/forgot-password` send logged-in users to `?next=`
   (only same-site paths) or `/app`; `/reset-password`, `/verify-email` and `/invite/:token` do not,
   because their links must work while logged in.
5. **Login form contract for recorded runs**: fields labelled "Email" and "Password", button
   "Log in" (what `ui_run.login` drives). T-042 should keep these labels.
6. **Extra tokens** beyond the ADR-0019 minimum: `surface-muted`, `primary-hover`, `primary-soft`,
   `{success,warning,danger,info}-soft`, `agent-fg`; `.light` / `.dark` on any element force a theme
   for that subtree (used by the gallery's logo panels). All are covered by the contrast test.
7. **Act-as header**: registered during render (child views fetch in effects that run before the
   provider's) and re-registered in an effect; switching founder reloads that company's queries.

### Round 1

1. **Markdown prose colors (fixed).** `tailwind.config.ts` now builds the typography variables with
   `tokenColor()`, which gives plain token colors (`rgb(var(--color-primary))`, and
   `rgb(var(--color-text) / 10%)` for `kbd-shadows`) with no `<alpha-value>`. It covers every variable the
   plugin defines (18 roles, kbd included). Each `--tw-prose-invert-*` twin gets the same token, so even a
   stray `prose-invert` can't bring the plugin's grays back. `Markdown` no longer has `dark:prose-invert`,
   because the tokens switch with `.dark`. New `src/design/prose.test.ts` runs the real config through
   Tailwind. It checks that every generated `--tw-prose-*` variable is `rgb(var(--color-<token>))` for a token
   defined in both themes, that there is no `<alpha-value>` and no hex/rgb literal in the prose rules, and
   that `Markdown` has no `prose-invert`. I ran it against the round-1 config and it failed there, as it
   should. The `/design` Markdown sample now also has a blockquote, inline code and a code block. The
   feature run measures computed colors in Chromium against the resolved tokens. Light: body
   `rgb(15, 23, 42)` = text, link `rgb(27, 54, 130)` = primary, `pre` background `rgb(240, 243, 248)` =
   surface-muted. Dark: link `rgb(147, 180, 255)`, `pre` `rgb(22, 30, 47)`, all equal to their tokens.
2. **Company card focus (fixed).** The `/app` company card link now uses the shared `focusRing` and fills
   the card (`p-4`, `rounded-lg`), so the ring outlines the whole card. `app.test.tsx` checks the link has
   the ring classes and that Tab reaches it. The feature run tabs to it on a stubbed `/app` and finds the
   box-shadow ring. A new `components.test.tsx` scan fails on any `.tsx` source line that sets
   `focus-visible:outline-none` without a `focus-visible:ring-*` beside it.

The non-blocking notes are unchanged in this round. The PlanGate copy for Team users is best handled when T-014 defines that error.

## Review

(Appended by the Reviewer: `### Round N`, `Verdict: …`, findings. At most 3 rounds.)

### Round 1
Verdict: CHANGES_REQUESTED

`bash scripts/verify.sh T-011` passes on cc04a2a (pytest, `npm ci`/build/test, recorded run with 18 checks). The run log and screenshots show the acceptance criteria working: gallery sections, theme persisting across reloads, focus ring on each header stop, logged-out redirect, 390 px checks, first-load budget, the shell with a stubbed API in demo and non-demo mode. Scope, the ADR-0025 npm set, the client (CSRF, timeouts, retries, envelope, act-as) and `ui_run.py` match the ticket and ADRs. Two defects block the merge:

Blocking:
1. frontend/tailwind.config.ts:5 and :85-104, frontend/src/design/components/Markdown.tsx:8: `Markdown` does not use the tokens in either theme. (a) The typography overrides reuse `token()`, which includes Tailwind's `<alpha-value>` placeholder. Tailwind only fills that placeholder in color utilities, so the built CSS contains `--tw-prose-links: rgb(var(--color-primary) / <alpha-value>)`, which is an invalid color. I measured it in Chromium against the built CSS: in light mode, links render in body-text color `rgb(15,23,42)` rather than primary `rgb(27,54,130)`, `pre` has no background, and table borders fall back to currentColor. (b) `dark:prose-invert` switches dark mode to the plugin's own gray hex palette (body `#d1d5db`, links `#fff`, `pre` `rgb(0 0 0 / 50%)`). Those colors are not tokens and the AA test never checks them. This breaks AC2 ("components use tokens only (no hex colors)") for the component that chat (T-018) and the legal documents (T-020) will render with. The source-scan test misses it because the hex values come from the plugin. Done looks like: the prose variables are plain token colors (for example `rgb(var(--color-primary))`, with no `<alpha-value>`), `dark:prose-invert` is removed (the tokens already switch with `.dark`), and a test checks that the generated prose variables are valid token colors in both themes. For example, parse the built CSS, or assert that `tailwind.config` typography values contain no `<alpha-value>` and that Markdown has no `prose-invert`.
2. frontend/src/features/onboarding/index.tsx:41: the company card link on `/app` (`CompaniesPage`, the first page after login) sets `focus-visible:outline-none` and has no ring in its place, so keyboard focus on a company is invisible. This breaks AC10 ("keyboard accessible with visible focus"). Done looks like: the link uses the shared `focusRing` (or the card shows a `focus-within` ring), and a test or the feature run covers it.

Non-blocking:
- `PlanGate`/`planGateCopy` (frontend/src/design/components/PlanGate.tsx:36): for the company limit when no next plan exists (a Team user, ADR-0038 "Contact support to add more"), `required_plan` is absent and the heading becomes "Upgrade to Launch for more companies". That is wrong copy for a Team user. Worth handling when T-014 defines that error. Without `details.feature`, prefer the server message, or omit the upgrade heading when the current plan is at or above the fallback.
- `running_app` starts uvicorn with `cwd=REPO_ROOT` and no explicit settings, so `load_settings(None)` still merges a developer's `.env` for any key `compose_env` removed (for example `BRAND_NAME`, `SUPPORT_EMAIL`, `SECRET_KEY`). The run is therefore only as hermetic as the local `.env`. Consider setting every stripped key explicitly, or running from a directory without a `.env`.
- `theme.test.tsx` "the build output has no inline scripts" passes without checking anything when `dist/` does not exist. Assert that at least one HTML file was found, or `skipIf` with a reason.
- `AllowanceBanner` keeps `hit` for the rest of the session after one `usage_limit` error, even after an upgrade. Reset it when the subscription query changes.
- `og:image` is a relative URL. Most crawlers need an absolute URL (it can be filled from `APP_BASE_URL` later).
- `scrollbar-gutter: stable` leaves a visible strip to the right of the sticky headers in the desktop screenshots. Cosmetic.
