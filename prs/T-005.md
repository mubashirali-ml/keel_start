## Summary

This PR implements the T-001 stubs in `persistence/engine.py` and `persistence/repository.py`.

- **Engine.** `create_db_engine(url)` supports SQLite and PostgreSQL only. On SQLite it sets
  `check_same_thread=False`, runs `PRAGMA foreign_keys=ON` on every connection, and uses
  `StaticPool` for `sqlite://`. On PostgreSQL it uses `pool_pre_ping=True` and passes
  `options=-c statement_timeout=15000`. `postgresql://`, `postgres://` and
  `postgresql+psycopg2://` URLs become `postgresql+psycopg://`. Any other URL raises `ValueError`.
- **Migrations.** `init_db(engine)` runs Alembic `upgrade head` in code. It loads the repo's
  `alembic.ini` and passes the connection through `config.attributes`. It never changes the
  app's logging. `schema_is_current(engine)` compares the database heads with the script heads.
  It returns False for an empty database, for one behind head, and for one it cannot reach.
- **Repository.** Built on SQLAlchemy Core over the T-001 tables. Only pydantic objects come out.
  Each method runs in its own transaction. `transaction()` binds this same repository to one
  connection for the current thread or task through a per-instance `ContextVar`. Inside the block
  the yielded object and `repo` are the same object. Nested blocks join the outer one, and other
  threads are not affected.
- **Behaviour choices inside the ADR contract:**
  - Unknown case, document, build or user ids raise `NotFoundError`, including `list_*` on an
    unknown case. The one exception is `list_cases`, which returns whichever of the given ids
    exist.
  - `append_messages` first runs a no-op `UPDATE` on the case row. This takes a row lock on
    PostgreSQL and the write lock on SQLite, so concurrent appends keep `seq` without gaps. It
    always assigns `id`, `case_id` and `seq`. It keeps a `created_at` the caller already set
    (useful for seeded history) and stamps "now" otherwise.
  - `save_document` makes the optimistic check twice: once by reading the stored version, then
    again with `UPDATE ... WHERE version = expected_version`. A save without `expected_version`
    on a document that already exists raises `StaleVersionError`.
  - A second document with the same (case, kind, founder) raises `ConflictError`. So does a site
    build whose (case, version) already exists.
  - Every signature in `doc.signatures` must be for `doc.version`, otherwise `ValueError`. Older
    signature rows stay for history.
  - `list_documents` sorts by `DocumentKind` declaration order, then by founder order in the case
    facts. Founder-less documents come first within a kind. Signatures come back in signing order
    (`signed_at`, then `founder_id`).
