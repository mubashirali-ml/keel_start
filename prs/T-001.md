## Summary

Creates the whole `launch_agents/` package of ADR-0024 (150 modules) so every later ticket can be
built in parallel against typed contracts:

- **Implemented:** settings with `APP_ENV`, per-environment defaults, the ADR-0022 LLM selection,
  per-agent models/efforts, `Settings.plans()`, redacting `repr` and every production guard
  collected into one `ConfigError`; the retry helper and `Deadline`; the whole domain vocabulary
  (case facts and `apply_patch`, messages/handoffs/actions, state, cap table, documents with
  e-signature evidence, website/QA, guide, the 51 curated states, errors, views, accounts and
  `CaseAccess`, plans v2 and entitlements, jobs, email); the LLM interface, deterministic
  `FakeLLM` and usage sinks; every port with its fake (`FakeDomainChecker`, `FakeSiteHost`,
  `UnconfiguredSiteHost`, `FakeEmailSender`, `RecordingMailer`, `RecordingNotifier`,
  `FakePaymentGateway` with signed webhooks, `StaticEntitlements`, `InlineJobRunner`); the full
  21-table schema on one `MetaData` and the frozen migration `0001_initial`; the agent/turn types,
  the Manager greeting, empty agent `fake.py` modules, the service protocols, the `Services`
  dataclass and a `create_app` skeleton (health, error envelope, CORS, SPA fallback).
- **Stubbed (exact signatures + docstrings, body `raise NotImplementedError("... implemented in T-0NN")`):**
  237 functions/methods across 28 owner tickets (the feature run lists every one with its owner).
- **Tests:** `pytest.ini`, shared fixtures in `tests/conftest.py`, the ADR-0025 skip hook and the
  `postgres` marker, and `tests/test_foundation.py` (575 tests).

## Notes for later tickets (choices made inside T-001's paths)

- **Founder ids** (`apply_patch` is pure and sees only the facts): a new founder gets one above
  the highest id the facts held before the patch, so removed ids are never refilled
  (`f1, f3` + new -> `f4`), including a removal and an addition in the same patch.
- **`audit_log.case_id`** cascades on company delete (privacy: "delete the company and
  everything in it"); `audit_log.document_id` has no FK, so audit outlives `delete_document`.
  `invites.invited_by` and `admin_audit.admin_user_id` are plain text (history; the admin CLI
  writes `"cli"`).
- **Routers** declare full paths (`/api/...`, as in the ADR-0032 table) and `create_app`
  includes them without a prefix (`api/routes/__init__.py: ALL_ROUTERS`).
- **`require_feature` messages** come from the plans: "Publishing your website is included in
  the Launch and Team plans." etc. (`domain.billing.feature_required_message`), matching T-013/T-015.
- **`StaticEntitlements(plan)`** returns that plan for every user id, also `None`.
- **`FakePaymentGateway`** price ids: `fake_price_id(plan, interval)` -> `price_fake_launch_monthly`
  etc.; configured `STRIPE_PRICE_*` ids are recognised too. `cancel(customer_id, *, at_period_end=False)`.
- **`FakeSiteHost.fail_next(n)`** and **`FakeDomainChecker(..., clock=)`** are optional extras for
  the failure path and deterministic timestamps.
- **Settings:** `llm_provider` defaults to `"fake"` on the model (`load_settings` always sets
  it); `frontend_dist` reads `FRONTEND_DIST`. Negative `PLAN_*` numbers are refused in every
  environment; a paid plan at 0 / Free above 0 only in production (ADR-0038).
- **Stub-signature test** accepts extra trailing parameters only when they are optional, so an
  owner may add e.g. a keyword with a default without breaking `tests/test_foundation.py`.

### Round 1
Verdict: CHANGES_REQUESTED

Checked: the full diff (161 files), `bash scripts/verify.sh T-001` (PASS, 575 tests passed, 0 skipped), the
recorded run in `evidence/T-001/run.log` (it shows every item the ticket's feature run asks for), the migrated
schema against `tables.py` (columns, PKs, FKs with ondelete, unique constraints and indexes are identical on
SQLite), domain models and enums against ADR-0008/0009/0013/0014/0015/0016/0026/0028/0029/0031/0032/0038, the
production guards of ADR-0021/0038, the LLM selection of ADR-0022, the import direction of ADR-0024 and the
ADR-0025 lazy imports.

Blocking:
1. tests/conftest.py:45-56 and :82-91 — `missing_adr0025_package` treats any `ImportError` whose `name` starts
   with an ADR-0025 package as "not installed", and `pytest_runtest_makereport` / `_Adr0025Module.collect` then
   turn the failure into a skip. That hides real bugs in installed packages. I checked it: with stripe and
   alembic installed, a test doing `from stripe import ThisSymbolDoesNotExist` and one doing
   `import alembic.no_such_module` are both reported as `SKIPPED ... package stripe/alembic not installed
   (ADR-0025)`, and pytest exits 0. Every later ticket that imports an ADR-0025 package (T-026, T-029, T-031,
   ...) would pass `verify.sh` with broken code. — Done looks like: skip only when the top-level ADR-0025
   package itself cannot be imported, i.e. a `ModuleNotFoundError` for exactly that root module name (or
   `importlib.util.find_spec(root) is None` / `sys.modules[root] is None`). A plain `ImportError` (bad symbol) and
   a missing submodule of an installed package must still fail. Add tests for both cases: they must fail, not
   be skipped.
2. launch_agents/config.py:129-134 — `repr(settings)` redacts only fields whose name contains
   key/secret/token/password. The database password in `db_url` still shows: `load_settings({"LAUNCH_DB_URL":
   "postgresql+psycopg://app:S3cretPw@db/launch"})` prints `S3cretPw` in `repr()` and `str()`. AC 5 says
   "Secrets never appear in `repr(settings)`", and ADR-0021 says no secret reaches a log line. The production
   `db_url` is a PostgreSQL URL with credentials. A password in `llm_base_url` leaks the same way. — Done looks
   like: URL settings (`db_url`, `llm_base_url`) show with the password masked in `repr`/`str`, for example
   with `sqlalchemy.engine.make_url(url).render_as_string(hide_password=True)` or by masking any `user:pass@`
   part. Extend `test_secrets_never_appear_in_repr` to cover a Postgres URL with a password.

Non-blocking:
- launch_agents/domain/types.py:168-169 and the PR note "removed ids are never refilled": this holds only
  within one patch. Across patches the highest id is reused: facts {f1, f2}; patch 1 removes f2; patch 2 adds
  Carol -> she gets `f2`. ADR-0008 says ids are "never reused". `apply_patch(facts, patch)` cannot prevent this
  because `CaseFacts` keeps no high-water mark, so this cannot be fixed inside T-001's contract. It matters
  later: a membership linked to `f2` (ADR-0026) would then sign as Carol. Please reword the PR note so it
  states the real guarantee, and raise the gap with the Supervisor (for example a high-water mark in
  `CaseState`, or T-027 unlinking memberships when a founder is removed).
- launch_agents/security/rate_limit.py:32 — both `llm` rules are named `user`. If T-032 builds the
  `rate_limits` key from the rule name alone, the per-minute and per-day windows share the row
  `(key, window_start)` at 00:00 UTC. A note in the docstring telling T-032 to include `window_s` in the key
  would prevent that.
- .env.example:70, :118, :135 set `EMAIL_PROVIDER=console`, `JOBS_EMBEDDED_WORKER=1` and `LOG_FORMAT=text`
  explicitly. If someone uses the file as a production env template, these silently override the production
  defaults. The email one trips a guard; the other two do not. Leaving them empty or commented, with the
  default named in the comment, would be safer.
- launch_agents/ports/payments.py:201 — a non-ASCII `t=` value in the signature header raises
  `UnicodeEncodeError` instead of `WebhookSignatureError`. Fake only, but cheap to catch.
