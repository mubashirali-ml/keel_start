## Summary

The backend's default brand is now **Keelstart** (ADR-0041). It is still one constant,
`BRAND_NAME` in `domain/constants.py`, so settings, the Manager greeting and the PDF/DOCX
renderer defaults pick it up without any change to their code. The three plans now say
"Email support" (Free), "Email support" (Launch) and "Priority support" (Team), with no
reply time (ADR-0042). Each label is still the last pricing-card highlight. No signature,
type, enum value or field changed. The foundation tests change only the literals that
spelled the old brand or the old labels. They also gain the ADR-0041 brand guard, a test
of the renderer defaults and the ADR-0042 no-promise check.

## Files changed

- `launch_agents/domain/constants.py`: `BRAND_NAME = "Keelstart"`. The comment above it and the module docstring cite ADR-0041.
- `launch_agents/domain/billing.py`: the `_PLAN_BASE` support labels follow ADR-0042. "Support labels pending Q-009" is replaced by an ADR-0042 reference. The `Plan.support_label` example comment and the module docstring now cite ADR-0042.
- `.env.example`: `BRAND_NAME=Keelstart`, and its comment cites ADR-0041. No other line changed.
- `tests/test_foundation.py`: the old brand and label literals are updated. The PublicConfig sample and the greeting now compare against `BRAND_NAME`. Section 16 is rewritten as the ADR-0041 brand guard and ADR-0042 support checks, and there is a new `.env.example` brand-comment test.
- `evidence/T-047/feature_run.py`, `evidence/T-047/run.log`: the recorded feature run.
